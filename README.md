## How it is built

A hand-written static site with no framework and no npm dependencies.

- **HTML** is generated by one Node.js script, [`src/build.mjs`](src/build.mjs), from content in [`src/data.mjs`](src/data.mjs) (profile, experience, skills, featured work, testimonials) and [`src/framer-cases.mjs`](src/framer-cases.mjs) (case-study pages).
- **CSS and JavaScript** are plain files: [`static/styles.css`](static/styles.css) and [`static/main.js`](static/main.js). Links to them carry a content hash (`?v=…`), so browsers fetch new versions after each change.
- **Fonts:** Krona One and Inter from Google Fonts.
- **Hosting:** Vercel, deploying from the `main` branch of this repository. Vercel runs `npm run build` and serves the generated `dist/` folder.

### Project structure

```text
src/
  build.mjs          builds every page plus robots.txt, sitemap.xml, llms.txt, site.webmanifest
  data.mjs           site URLs, profile, experience, skills, proof figures, featured work, testimonials
  framer-cases.mjs   case-study content (blocks of headings, text, images)
static/
  styles.css, main.js
  profile.webp, profile-portrait.jpg      portrait (hero and structured data)
  favicon.ico, favicon-32.png, favicon-96.png, apple-touch-icon.png, icon-192.png, icon-512.png
  og-image.jpg                            1200×630 social-sharing image
  logos/                                  company logos
  work/                                   case-study images, covers and slides
  resume.pdf
dist/                generated by the build (git-ignored)
PORTFOLIO-AUDIT.md   design and content audit notes
```

### Run it locally

Requires Node.js (the build uses only built-in modules; developed on Node 22).

```bash
npm run build
```

```bash
python3 -m http.server 4321 --directory dist
```

Then open http://localhost:4321. There is no lint or test script; the build prints `Built 16 pages → dist/` when it succeeds.

To edit content, change `src/data.mjs` or `src/framer-cases.mjs` and rebuild. Every `<head>` is generated by `head()` in `src/build.mjs`.

## Features

- Home page: hero with an opening animation, proof figures, three flagship case studies, more work and concepts, how I work, design-system specimen, experience timeline, Figma activity, skills, testimonials and contact.
- 14 case-study pages under `/work/`, with chapter navigation and next-case links.
- Accessibility: a skip link, semantic landmarks, one `h1` per page, an `alt` attribute on every image (empty for decorative ones), visible keyboard focus. Motion respects `prefers-reduced-motion`, and visitors with reduced motion can opt in with the hero's "Play motion" button.
- Responsive from phones to wide desktops.

## SEO and discoverability

All of this is generated by `src/build.mjs`; nothing below is hand-edited in `dist/`.

| What | Where | Notes |
|---|---|---|
| Canonical origin | `SITE` in `src/build.mjs` | `process.env.SITE_URL` if set, otherwise `site.live` in `src/data.mjs` (the Vercel URL). Used by canonical tags, Open Graph, Twitter cards, JSON-LD, sitemap, robots.txt and llms.txt. |
| Titles and descriptions | `head()` | Unique per page. Home: "Kavuthamraj GS – Senior Product Designer & UI/UX Portfolio". Case pages: "<Project> – UX Case Study \| Kavuthamraj GS" (concepts say "UI/UX Concept"). Descriptions are cut at a word boundary under 160 characters. |
| Robots | `head()` | Indexable pages: `index,follow,max-image-preview:large`. `404.html`: `noindex`, no canonical, not in the sitemap. |
| Open Graph and Twitter | `head()` | Home uses `og-image.jpg` (1200×630). Case pages use their own cover or slide. |
| Structured data | `homeLd` and `fcPage()` | Home: one JSON-LD `@graph` with `WebSite`, `ProfilePage` and `Person` (stable `@id`s, `sameAs` LinkedIn and Behance, `knowsAbout`, `alumniOf`). Case pages: `CreativeWork` (author is the same `Person`) and a `BreadcrumbList`. |
| Sitemap | `/sitemap.xml` | Home plus the 14 case-study pages, on the canonical origin. |
| robots.txt | `/robots.txt` | Allows everything and points to the sitemap. |
| llms.txt | `/llms.txt` | A plain-text summary of the profile and links to each case study, for AI tools that read it. It is a courtesy, not a ranking factor. |
| Favicons | `static/` | Made from the professional portrait: a round face crop for `favicon.ico` (16, 32 and 48px), `favicon-32.png` and `favicon-96.png`, plus a square crop for `apple-touch-icon.png` (180px) and the manifest icons (192 and 512px). |
| Web manifest | `/site.webmanifest` | Name, colours and the 192 and 512px icons. |
| Verification | `site.verify` in `src/data.mjs` | Paste the Google Search Console or Bing Webmaster Tools HTML-tag code (only the `content` value). The meta tag is printed only when a value is set. |

## Search Console and Bing, now (Vercel URL)

1. In Google Search Console, add a **URL-prefix** property for `https://kavuthamraj-website-red.vercel.app/`. Choose the HTML tag method, copy the `content` value into `site.verify.google` in `src/data.mjs`, push, wait for the deploy, then verify.
2. Submit `https://kavuthamraj-website-red.vercel.app/sitemap.xml` under **Sitemaps**.
3. In Bing Webmaster Tools, import the site from Search Console (or use `site.verify.bing`) and submit the same sitemap.

## Moving to the custom domain

The custom domain currently shows the registrar's parking page. **Do not switch the canonical origin or add redirects until `https://www.kavuthamraj.com` serves this site over HTTPS.** Until then the Vercel URL stays canonical.

### 1. Connect the domain (manual, Vercel and the registrar)

1. Vercel → Project → **Settings → Domains**: add `www.kavuthamraj.com` and `kavuthamraj.com`. Make `www.kavuthamraj.com` the primary domain and set `kavuthamraj.com` to **redirect to `www.kavuthamraj.com`** (permanent, 308).
2. At the domain registrar: turn off parking and forwarding, then create the DNS records Vercel shows for each domain (usually an `A` record for `kavuthamraj.com` and a `CNAME` for `www`). Use the exact values Vercel displays.
3. Wait until Vercel shows both domains as **Valid Configuration** with a certificate issued, and check:
   ```bash
   curl -sI https://www.kavuthamraj.com/
   ```
   ```bash
   curl -sI https://kavuthamraj.com/
   ```
   The first should return `200` from Vercel; the second should return `308` with `location: https://www.kavuthamraj.com/`.

### 2. Switch the canonical origin (no code change)

Vercel → **Settings → Environment Variables**: add `SITE_URL` = `https://www.kavuthamraj.com` for the **Production** environment only, then redeploy. Canonical tags, Open Graph, JSON-LD, sitemap, robots.txt and llms.txt all move to the new domain. Keep `SITE_URL` unset for Preview, so preview builds keep pointing at the production Vercel URL.

To make it permanent in code instead, change `site.live` in `src/data.mjs` to the new domain.

### 3. Redirect the old Vercel URL (only after step 2 is live)

Add a `vercel.json` at the repository root:

```json
{
  "redirects": [
    {
      "source": "/:path*",
      "has": [{ "type": "host", "value": "kavuthamraj-website-red.vercel.app" }],
      "destination": "https://www.kavuthamraj.com/:path*",
      "permanent": true
    }
  ]
}
```

The `host` condition matches only the production alias, so preview deployments (which get their own `*.vercel.app` hostnames) keep working, and the custom domain itself is never redirected, so there is no loop. Paths are preserved one-to-one (`/work/titan.html` → `/work/titan.html`). Vercel serves preview deployments with an `X-Robots-Tag: noindex` header by default; confirm with `curl -sI` on a preview URL.

Then check:

```bash
curl -sI https://kavuthamraj-website-red.vercel.app/work/titan.html
```

It should return `308` with `location: https://www.kavuthamraj.com/work/titan.html`.

### 4. Tell search engines (manual)

1. Google Search Console: add a **Domain** property for `kavuthamraj.com` (DNS TXT verification), then submit `https://www.kavuthamraj.com/sitemap.xml`.
2. On the old Vercel URL property, use **Settings → Change of address** to point to the new property if Search Console offers it for that property; if not, the permanent redirects and the new sitemap carry the move.
3. Bing Webmaster Tools: add the new site, submit the new sitemap, and use **Site Move**.
4. Keep the old property for a few months to watch the move, and update the domain on LinkedIn, Behance and the résumé.
